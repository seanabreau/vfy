# Changelog 0.0.x

## [Unreleased]

### Command-line interface

- Accept `-q/--quiet` after `vfy coverage html`, `json`, `xml`, `lcov`, and
  `combine`, the commands that accept it in Coverage.py.
- Link `vfy test --help` to the compatibility page on the documentation site,
  https://vfy.neocline.com/.

### Coverage

- Give `source` and `source_pkgs` precedence over collection-time `include`,
  as Coverage.py does. When both filters are set, vfy emits `include-ignored`.
  Suppress it with `[run] disable_warnings`.
- Honor `[report] show_missing` and `skip_covered` in `--cov-report=term`
  output from `vfy test` and `pytest -p vfy.pytest_plugin`, as pytest-cov
  does. `term-missing` and `:skip-covered` still turn them on.
- Preserve coverage for one-line functions and lambdas across context switches
  on CPython 3.13 and later.
- Report missing coverage data as an error, as Coverage.py does.
  `vfy coverage report`, `html`, `json`, `xml`, `lcov`, and `annotate` exit
  with status 1 and `No data to report.` when no measured file remains, so
  `--fail-under` cannot pass on an empty data file. `vfy coverage combine`
  exits with status 1 and `No data to combine` when it finds no shards.
  When pytest requests a report or checks a positive coverage threshold with
  empty data, vfy prints pytest-cov's `Failed to generate report: No data to
  report.` warning.
- Run custom `pytest.Item` subclasses, such as items collected from data
  files, under `pytest -p vfy.pytest_plugin --cov`.
- Write reports, JUnit XML, and other output files as Coverage.py does with
  `open(path, "w")`: through symlinks to their final target, keeping an
  existing file's permissions, and giving a new file `0o666` less the umask.
  Regular files are still replaced atomically, and a device or FIFO such as
  `/dev/stdout` or `>(cat)` is written in place instead of being replaced. A
  new data file gets `0o644` less the umask, as SQLite gives Coverage.py's.
- Report the branches Coverage.py reports for a `with` statement that ends the
  suite of a `with` statement nested in a third, such as three nested `with`
  blocks with no statements after the innermost.
- Measure branch coverage on CPython 3.12 and 3.13 with fewer monitoring
  callbacks. Forward branch events never changed the recorded arcs, so vfy no
  longer requests them unless decision coverage needs their outcomes.

### Test-effectiveness tools

- Select mutation sources in a project reached through a symlinked directory,
  such as a macOS temporary directory, when an ancestor directory is named
  `tests` or `.venv`.

### Test execution

- Run custom `pytest.Item` instances returned directly by `pytest_collect_file`
  under `vfy test --engine=native`.
- Exit quietly with status 1 when the stdout reader closes during `vfy test`
  or `vfy coverage report`.
- Give `pytest_fixture_setup` and `pytest_fixture_post_finalizer` hooks in the
  native engine pytest's `FixtureDef` attributes `argnames`, `baseid`, `params`,
  and `ids`, and its representation, so plug-ins such as pytest-trio can set up
  fixtures.
- Accept an `ExceptionInfo` in `Traceback.filter` and provide `Config.rootdir`
  and `Config.inifile` in the native engine, as pytest 9 does.
- Honor `-W error` and `filterwarnings` when the native engine loads
  `conftest.py` at startup.

### Affected-test selection

- Print the prepared test selection before pytest's session output with
  `vfy test --engine=native`. Report changes discovered during collection after
  pytest exits. Outside a Git repository, `vfy test --all` identifies the explicit
  request as the reason to run the full suite.
- Select tests in a repository that contains Git submodules, including
  `vfy test --engine=native` coverage runs and portable CI baselines. Selection
  identifies each submodule by the commit the repository records for it, and
  runs the full suite when a submodule is uninitialized, has uncommitted
  changes, or is checked out at another commit. CI selection errors name the
  file they could not read.
- Bytecode under `__pycache__`, including bytecode that vfy's assertion
  rewriting writes, does not count as a source change when a repository tracks
  it. A `vfy test --engine=native` coverage run in a fresh checkout of such a
  repository runs its tests instead of failing with "source changed after the
  CI plan was prepared".

### Documentation

- Add a [staged migration guide](https://vfy.neocline.com/getting-started/adopt-vfy/)
  for existing pytest projects, including separate coverage reports and CI gates.
- The CI guide's main workflow runs `vfy test --all` with a coverage threshold
  in one job, and keeps pytest with vfy coverage as the route for suites that
  need pytest plug-ins.

## [0.0.1]

vfy 0.0.1 is the first release. It is Alpha: interfaces can change, and the
test runner supports a documented subset of pytest. See the
[compatibility contract](https://github.com/seanabreau/vfy/blob/main/docs/about/compatibility.md) for versions, supported
behavior, and limits.

On Linux or macOS with CPython 3.12+ and uv, install vfy in your project and run
your tests with coverage:

```console
uv add --dev vfy
uv run vfy test --cov=src --cov-branch --cov-report=term-missing
```

Replace `src` with your source directory. The command prints missing lines and
branches and saves `.coverage`. The
[coverage tutorial](https://vfy.neocline.com/getting-started/quickstart/) provides
a complete example with source files and expected output.

### Platforms and installation

- The package requires CPython 3.12 or newer and has no required Python
  dependencies. Wheels use the CPython 3.12 stable ABI. The release workflow
  builds them for Linux x86_64 and aarch64 (glibc and musl), and macOS x86_64 and arm64.
- `vfy[pytest]` adds `pluggy>=1.5,<2` and `pytest>=9.1` for the optional
  `pytest-native` and `pytest` engines.
- `vfy test` and `vfy mutate` need Linux or macOS, and independent mutation needs
  Linux.

### Coverage

- Line and branch coverage use `sys.monitoring` and read and write Coverage.py
  schema-7 data. Compatibility is compared with Coverage.py 7.15.4.
- `vfy coverage` provides `run`, `report`, `html`, `json`, `xml`, `lcov`,
  `annotate`, `combine`, `erase`, `debug data`, and `check`. Reports include
  terminal text, Markdown, HTML, JSON, Cobertura XML, LCOV, and annotated source.
- The Markdown summary follows Coverage.py's table layout. Summary reports
  accept descending sorts such as `--sort=-cover`. `--fail-under` uses the
  requested report precision.
- The typed `Coverage` and `CoverageData` Python APIs follow the documented
  Coverage.py interfaces and public plug-in protocols: file tracers,
  configurers, file reporters, and dynamic contexts.
- `CoverageData.add_file_tracers()` rejects conflicting batches atomically.
- Subprocess, `fork`, and `multiprocessing` coverage write isolated shards.
  `combine` validates every shard before replacing the destination.
- Source, include, omit, context, exclusion, and `[paths]` alias settings follow
  Coverage.py. Reports use the Python source inventory saved during collection.
  Unknown or invalid configuration fails before work begins.
- `vfy.pytest_plugin` implements the pytest-cov 7.1 options for direct `pytest`
  runs, and `vfy.pytest_reporting` provides test-results HTML and metadata there.

### Test execution

- `vfy test` runs pytest-style tests with the native engine by default. The
  engine does not need pytest: it provides configuration parsing, collection,
  imports, and assertion rewriting, and returns pytest's exit statuses.
- Supported features include fixtures, parametrization, markers, `unittest`
  cases, text doctests, capture, logging, JUnit XML (`--junitxml`), static
  test-results HTML (`--html`), `async def` tests and fixtures (pytest-asyncio
  1.4.0 behavior), Hypothesis property tests, POSIX signal timeouts, and the
  disabled mode of pytest-benchmark's fixture.
- `-n`, `-j`, and `--workers` run tests in parallel. `--native-scheduling`
  chooses `file`, `scope`, `cases`, `striped`, or `demand` assignment.
  Independent parallel runs default to `demand`, claiming case batches as
  workers finish; serial runs retain collection order. Native runs default
  to `file`. Recorded durations in
  `.vfy/test-history.sqlite3` balance `file` and `scope` assignment.
- `--engine=pytest-native` runs tests and fixtures in Rust behind installed pytest
  (stable 8.0–8.4 and 9.0–9.2.0). `--engine=pytest` executes with installed
  pytest. Both support affected-test selection. The native engine supports
  pytest-xdist 3.8.0, pytest-mock, pytest-timeout 2.4, pytest-benchmark 5.3, and
  platformdirs fixtures. With `--numprocesses=0`, the native engine
  still calls pytest-xdist's protocol and reporting hooks. Plug-in discovery
  follows hooks that a plug-in's package re-exports.
- Independent workers provide pytest-xdist's `worker_id` and `testrun_uid`
  fixtures and `config.workerinput["mainargv"]` without pytest-xdist.
- Parallel workers retain the controller's pytest-randomly and pytest-random-order
  seeds.
- When one worker's interrupt stops its peers, the run exits with the status
  that worker requested.
- An unsupported option, plug-in, or platform fails with a diagnostic. vfy does
  not retry through stock pytest.

### Affected-test selection

- Selected runs rebuild complete coverage without cloning the complete
  baseline. Reading saved coverage shares context names across file partitions.
- `vfy test --all` records a passing
  baseline on a clean Git checkout. Later runs select the tests that reached
  uncommitted edits and merge fresh coverage with saved coverage. A run whose
  saved data cannot justify a subset executes the full requested scope and
  prints the reason.
- Independent selection supports unfiltered `safe` coverage runs without
  installed pytest. It preserves collection order and uses the full requested
  scope when the collected test inventory changes. When every edit stays in
  function bodies that only test calls ran, it collects only the test files
  that contain selected tests, including tests without recorded coverage
  contexts. `--plan-only` inspects the finalized plan without running test
  bodies or replacing saved coverage and history; `--plan-output` saves the
  plan to a file.
- `vfy explain PATH:LINE` lists the tests that reached a line. `--watch` reruns
  tests after changes settle. Portable CI baselines, saved selection plans,
  failure confirmation, and selection audits are available.

### Test-effectiveness tools

- `vfy mutate` applies one source change at a time in child processes, selects
  tests from saved coverage, and caches results. The independent engine runs
  serially on Linux. It collects the unchanged suite once and forks a child
  for each eligible function-body mutation; other mutations run in fresh
  interpreters. Cached results record
  the tests that ran. `--engine=pytest-native` adds `--workers` and file-isolated test
  execution. For mutated files excluded from coverage, vfy runs the full requested
  suite. Native mutation runs use Python tracebacks unless pytest traceback
  options are set. `--timeout-policy fixed` uses the configured mutation timeout
  as is; the default `adaptive` policy shortens it using clean-test durations.
- Mutation testing respects requested coverage settings and report thresholds.
  See the [mutation guide](https://github.com/seanabreau/vfy/blob/main/docs/guides/mutation.md)
  for baseline and execution details.
- `vfy coverage run --decisions`, `vfy test --cov-decisions`, and
  `vfy coverage check` collect and report decision, condition, and masking MC/DC
  (modified condition/decision coverage) data. The data is stored in `vfy_*`
  tables that Coverage.py ignores.

### Configuration and diagnostics

- vfy reads Coverage.py configuration and `[tool.vfy]` settings. `vfy config show`
  and `vfy config validate` report the resolved settings.
- `vfy diagnostics` reports the runtime, configuration, and selected engine, and
  `--collect` runs collection without test bodies. `vfy cache dir` and
  `vfy cache clean` manage the project-local `.vfy` directory.

### Known limitations

- The independent engine's assertion rewriting generates vfy-specific bytecode,
  and its `pytest` module is vfy's facade. Tools that inspect pytest's private
  rewriting or execution frames need `--engine=pytest`.
- vfy does not install a `coverage` command, provide Coverage.py's private
  modules or the byte format of `CoverageData.dumps()`, or support Python
  runtimes without `sys.monitoring`.
- Benchmark records describe their own workloads, revisions, and hosts; see
  [benchmarks](https://github.com/seanabreau/vfy/blob/main/docs/about/benchmarks.md).
